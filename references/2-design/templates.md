# 阶段 2 模板与准出清单

本阶段产出设计相关文档。模板里的占位内容一律替换成真实内容，空标题不要留在最终产出里。

## 文档模板

```markdown
# 设计说明：<需求名称>

## 页面与入口
| 页面 | 新旧 | 入口 | 对应 PRD 编号 | 出稿范围 | Figma page | Figma 链接 |
| --- | --- | --- | --- | --- | --- | --- |
（出稿范围写“整页”或“改动区域”；Figma page 写该页面在文件里对应的 page 名；Figma 链接填 `https://www.figma.com/design/<fileKey>/<名称>?node-id=<nodeId>`，`node-id` 用连字符形式如 `2-2`。**默认走 `generate_figma_design` 捕获通道，不耗额度，所以“额度用完了”不能作为拿不到链接的理由。** 确实拿不到时按下列写清原因，不允许留空：`待上传（capture 未成功，源已就绪）` / `待上传（一键导入包已就绪）` / `待上传（桥接不通，已排查）`）

## 状态覆盖
| 状态 | 是否必备 | 表现 | Figma frame / 链接 | 导出 PNG |
| --- | --- | --- | --- | --- |
| 正常态 | 必备 | | | |
| 空态 | 必备 | | | |
| 超长文案 / 多语言 | 必备 | | | |
| 极端数据 | 必备 | | | |
| 加载态 | 自行判断 | | | |
| 错误态 | 自行判断 | | | |
（加载态、错误态判断为不出稿时，在表下补一行理由，例如“该页面数据本地读取，没有加载过程”）

## 与现有设计规范的差异
（没有差异就写“无”；有差异说明原因。字体在 Figma 账号里缺失而降级替换时，必须写在这里）

## 改动点定位
| 改动点 | 关联 REQ | 在 Figma 稿上的位置（frame / 图层名） |
| --- | --- | --- |

## 出稿产物
（`figma-import/` 下的文件清单：`design-spec.json`、`html/`、按需的 `use-figma.js`；以及 `design-images/` 下的 PNG 清单。前两者由 `assets/figma-render.js` 从 spec 派生，`use-figma.js` 由 `assets/figma-compile.js` 派生，PNG 由 `assets/figma-shot.js` 生成，清单里不要出现手写的 HTML 或 Figma 代码。用 Markdown 图片语法直接展示 PNG，老页面未改动部分引用截图库里的真实截图）

## Figma 出稿记录
| 文件 | fileKey | sessionId | 页面 → page | 通道 | 提交方式 | 消耗额度 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
（文件名固定为 `<工作区名> / <需求标识>`；通道写 `generate_figma_design`（默认，捕获 DOM，豁免额度）或 `use_figma`（结构精确，计额度）；提交方式写“capture × N”或“一次提交 N 个状态”；消耗额度按通道如实填 `0 次` 或 `1 次`，一个需求的出稿成本应当可核对；状态写“已入画布”/“未授权未上传”/“capture 失败未入画布”）
```

## 准出检查清单：设计 → 技术方案
- 任务开始前就跑过 `assets/figma-auth.js check`，结果是可用（exit 0）；中途重新授权过的话，新 token 也验证通过；账号/计划/席位已记进需求卡片的环境信息
- 正常态、空态、超长文案、极端数据都有稿；加载态和错误态已给出保留或舍弃的判断和理由
- `design-spec.json` 存在且是设计源，`html/`、PNG、按需的 `use-figma.js` 都由自带的渲染/截图/编译脚本从它派生，没有手写 Figma 代码或 HTML 充当设计源的痕迹
- 老页面用的是截图库里最新的真实截图，改动区域在 spec 里重建了图层且出稿范围标为“改动区域”；新页面或库里缺图的页面标为“整页”
- 每个「页面 × 状态」是独立 frame，没有把多个状态拼进一张图；每个页面对应文件里一个独立 page
- **出稿消耗额度为 0**（走 `generate_figma_design` 捕获通道）；若走了 `use_figma`，出稿记录里如实填了消耗次数并说明为什么必须走计额度通道
- 稿子已真实写进 Figma 画布（有 node-id / frameId 和链接），或因授权 / 桥接 / capture 失败按降级路径处理并写明原因，没有空白
- 每条改动点都能在 Figma 稿上定位到具体 frame 或图层
- 使用的颜色、间距、字号来自项目现有规范；字体降级替换（含 `PingFang SC` → `Noto Sans SC` 这类）已写入「与现有设计规范的差异」
- 改动区域图与真实截图对齐，没有凭空重画整页
- `instance` / `image` 生成的占位框已在交付说明里标明需人工替换
- 该阶段未改动项目下的源码、配置、资源和既有文档
- 阶段 2 通过后设计源已归档到 `figma-import/` 与 `design-images/`，路径有效且没有唯一副本留在临时目录
- 「Figma 出稿记录」表已填全（fileKey / sessionId / page / 通道 / 消耗额度 / 状态），通道与实际调用的工具一致；文件名是「工作区名 / 需求标识」的形式，与仓库里的需求目录同名

（进入阶段 3（技术方案）前快速过一遍，不达标就补，不要带着缺口往下走。）

# 阶段 4 模板与准出清单

开发阶段没有独立的文档模板：这一阶段的产出是**代码、单元测试、debug 包、变更说明，以及更新后的技术方案开发内容状态**，由**开发 agent** 产出。代码怎么写看项目自己的规范，提交信息怎么写看本目录的 [README.md](README.md)（由主流程在提交时执行）。

变更说明不需要单开文件，写进技术方案的「开发内容」表即可——每完成一步就把对应行的状态改掉，收尾时整张表就是本次的变更说明。不要让表停留在「待办」，也不要攒到最后一次性回填。

## 回执里的三项必填

开发 agent 的回执必须包含（评审、测试、主流程都要用）：

```text
改动文件：<路径列表>
REQ 映射：<文件 → REQ-n>
建议提交切分：<第 1 条：覆盖哪些文件、做什么；第 2 条：…>
编译结果：<命令 + 结论>
单元测试：<命令 + 通过数/失败数 + 未覆盖步骤及原因>
debug 包：<产物路径 + 版本号 + 安装命令 + 启动命令>   # 无界面需求写“无界面，不产出”
未完成/遗留：<没有写“无”>
```

主流程据此拟提交信息并停下确认；开发 agent 自己**不执行 commit / push**。

## 准出检查清单：开发 → 代码评审

主流程校验通过才能进入阶段 5，不达标把缺口清单发回同一个开发 agent 返工。

- 代码由开发 agent（独立子 agent）产出，不是主流程代写
- 开发内容状态已更新到与代码实际进度一致
- 编译通过，且回执里有编译命令与结果
- **单元测试已写且真实跑通**，回执里有命令、通过数/失败数与未覆盖步骤及原因
- **单元测试没有引入新框架**（或引入时已按关键分叉停下确认）
- **有界面变化时 debug 包已产出**，并登记了路径、版本号、安装命令、启动命令
- 无遗留 TODO，或遗留项已显式记录
- 代码符合项目 AGENTS.md 规范（命名、注释语言、禁用写法、多语言资源）
- 回执给出改动文件清单与 REQ 映射，以及建议的提交切分
- 开发 agent 未执行 commit / push（提交由主流程确认后执行）
- 主流程拟好提交信息后，已把原文和文件清单一起给用户确认

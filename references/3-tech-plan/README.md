# 阶段 3：技术方案

技术方案把 PRD 翻译成可执行的开发计划。阶段 3 不写代码，只定方案；写完之后开发阶段照着「开发内容」表推进，不再重新讨论要做什么。

文档模板与准出清单见 [templates.md](templates.md)。

## 关注点

- **从 PRD 摘，不重新发明**：需求内容一节直接对应 PRD 的功能清单，改动的每一项都要能追到 `REQ-n`。
- **拆分到能估**：开发内容按可独立验证的步骤拆，每步标注依赖、关联需求和状态（待办 / 进行中 / 已完成 / 阻塞）。开发阶段就靠这张表跟踪进度，所以粒度要细到"做完这一步能编译通过"。
- **接口先定稿**：接口定义不允许留"待定"。前端和后端、调用方和被调用方要能在这一节对齐，字段、类型、错误码、空值语义都写清。
- **影响面写全**：受影响的既有功能、调用方、数据迁移、配置变更都要列，漏一项就是上线风险。
- **风险要带对策**：每条风险配一个可执行的对策，并给出回滚方案。

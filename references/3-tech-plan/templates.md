# 阶段 3 模板与准出清单

本阶段产出技术方案相关文档。模板里的占位内容一律替换成真实内容，空标题不要留在最终产出里。

## 文档模板

```markdown
# 技术方案：<需求名称>

## 需求内容
（本需求要改什么，从 PRD 摘出与实现相关的范围、行为和验收点，并标注对应的 REQ 编号）

## 开发内容
（按执行顺序列出，标明关联需求和前后依赖，不写工时和排期；状态只有 待办 / 进行中 / 已完成 / 阻塞 四种，每完成一步就更新，中断后从这里接着跑）
| 步骤 | 开发内容 | 关联需求 | 依赖 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | | REQ-1 | 无 | 待办 |

## 模块与改动点
（每条标注关联的 REQ 编号）
| 模块 / 文件 | 改动内容 | 关联需求 |
| --- | --- | --- |

## 接口定义
（每个接口一段，按下面的结构重复；接口填请求方法和完整 URL，含协议和域名，路径参数写成 {参数名}；入参只写本次变化，新增和删除分两行写，都没有变化时整格填“无”；枚举参数在“示例值”里列出全部枚举值）

| 项 | 内容 |
| --- | --- |
| 接口 | <请求方法> <完整 URL> |
| 入参 | 新增：<参数名，多个用、分隔><br>删除：<参数名> |
| 出参 | 见下表 |

| 参数 | | | 数据类型 | 参数含义 | 示例值 |
| --- | --- | --- | --- | --- | --- |

嵌套字段按层级拆列，只有第一列的表头写“参数”，后面几列的列名留空；字段名填在它所在的层级列里，父级只在所在块的第一行写一次。层级超过三层时用 `a.b.c.d` 压进一格，避免表格过宽；数据类型里带尖括号的写成 `array<object>`，用反引号包住避免被当成 HTML 标签。

颜色约定：本次新增的参数只把参数名标红，写成 `<span style="color:red">status</span>`；如果只是枚举新增，只把新增的枚举值标红，例如 `PENDING / RUNNING / <span style="color:red">ARCHIVED</span>`。如果目标环境不渲染 HTML 颜色，改成参数名加粗并补“（新增）”作为兜底。

出参没有变化时，出参那一行填“无”，并且不写下方参数表。入参有新增、出参却没变化时，把新增参数的类型、含义、示例值写在入参行的参数名后面，例如 `priority（string，枚举 LOW / NORMAL / HIGH，优先级）`。

## 影响面
（受影响的既有功能、调用方、兼容性、数据迁移）

## 风险与对策
| 风险 | 概率 | 影响 | 对策 |
| --- | --- | --- | --- |

## 回滚方案
（出问题怎么退回去：代码、配置、开关、数据，各自怎么做）
```

## 准出检查清单：技术方案 → 开发
- 文档由方案 agent（独立子 agent）产出，不是主流程代写；S 级需求由需求 agent 兼做时已在编排记录里注明
- 接口定稿，没有“待定”
- 影响面列全，包含受影响的既有功能
- 风险有对策，回滚方案可执行
- 开发内容标明关联需求、依赖和状态（待办 / 进行中 / 已完成 / 阻塞）
- 该阶段未修改项目下任何源码、配置、资源或测试

（主流程校验通过才能进入阶段 4（开发）；不达标把缺口清单发回同一个方案 agent 返工。）
